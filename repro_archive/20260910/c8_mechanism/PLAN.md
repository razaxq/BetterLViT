# C8 提升原因分析

分析对象为冻结来源的C4、C8和P10历史实验；目标是区分观察到的误差变化、代码保证的作用路径与尚未确立的因果解释。本轮不训练新模型、不修改已有权重、不重新读取Test图像或调整阈值。

## 证据范围

1. 复核完整训练配置、最佳epoch、评估脚本和C4/C8代码差异。
2. 从原始2113张Test及1429张Val逐图结果重建TP/FP/FN，核对所有宏平均。利用对称代数分解量化IoU变化中FP和FN变化的贡献；这不是因果干预。
3. 比较GT总病灶面积四分位、基线过分割/欠分割、逐图胜负、改变量分布和尾部敏感性。所有分层为事后描述，不用于Test选型或新的确认性显著性主张。
4. 从原始Best检查点只提取80轮历史、优化器与运行配置；不传输大型权重。
5. 只在Train固定32张图像上做C8 Best的梯度路径诊断：batch8、原Val预处理、eval模式保留BN、无optimizer步。按sha256('c8-mechanism-v1:'+mask_filename)选取，不能按诊断结果换样本。
6. 分别测量按真实系数加权的像素BCE、区域存在BCE、面积MSE、文本提及/数量项对四个共享编码器特征的梯度范数及其与主任务梯度的夹角。验证去掉推理辅助分支是否保持输出完全一致，文本loss是否没有视觉梯度路径，参数及BN哈希是否保持不变。

梯度快照仅说明该检查点/32张Train/eval模式的局部行为，不能替代训练全过程消融，也不能直接宣称某loss贡献了特定IoU百分点。普通深监督、存在/占比监督和文本独立旁支必须分别讨论。

现有Test已经被多轮开发查看，因此本分析不把它当作独立未触碰的留出集。图像bootstrap不代表训练种子重复；有可解析患者ID时另做相关性敏感性检查，不能为无ID样本虚构患者身份。

分析代码与计划先提交；梯度诊断来源SHA与原C8训练SHA分别记录。源代码、原始小型证据、统计结果和报告提交推送GitHub，使用现有文档台账记录结论。输出为中文Markdown分析报告，附独立计算脚本、JSON/CSV与必要图表。
