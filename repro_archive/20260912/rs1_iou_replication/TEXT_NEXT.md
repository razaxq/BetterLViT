# RS1 复验之后的文字实验顺序

目标是可重复的 macro IoU 增益。先完成两个 RS1 独立种子：按 PROTOCOL.md 的既定规则决定共同训练配方，不能给文字候选单独换 loss、增强或学习率。

## 候选与对照

将文字作用位置从最终输出的小范围纠错移到中间解码特征。候选使用同一报告的局部短语与视觉区域建立联系，并根据当前图像特征控制文本影响强度。文字是软提示，报告未提及某区域不等于该区域没有病灶。优先只加一个解码位置，避免同时改变多尺度、辅助监督、文本编码器和损失。

| 顺序 | 组别 | 需要分离的因素 |
|---|---|---|
| T0 | 原模型、选定共同配方 | 基准 |
| T1 | 同位置、相近容量的纯视觉适配器 | 增加参数/计算的收益 |
| T2 | 同位置、同宽度的普通图文注意力 | 普通文本融合的收益 |
| T3 | 短语绑定，保持其他配置与 T2 一致 | 短语结构的独立收益 |
| T4 | T3 加图像证据控制文本影响 | 控制文本影响的独立收益 |

先阅读实际 decoder 张量、报告可见 token 和历史文字诊断，写出准确位置、宽度、可训练参数、token/短语构造和缺失语义处理后再注册实现。表内是对照顺序，尚未声明这些模型已经编码或训练。普通 cross-attention 或门控本身不能当作新颖性证据。

## 执行顺序与推进

1. CPU 静态实现与小张量检查：禁用新增路径应回到原模型；文本 padding 不参与绑定；空报告可退回视觉；未提及不生成背景硬标签。显式防止以 mask 或 Test 内容构建推理提示。
2. GPU 空闲后做真实 Train preflight：检查初始化、反向梯度、诊断状态恢复、可用显存与吞吐；不与 RS1 正式训练抢 GPU。
3. 先对 T1/T2 做同预算可学习性诊断，再对 T3/T4 分项比较；固定共同初始化、trainable layers、优化器和更新预算。诊断只筛掉数值失败或不学习的路径，不把短训练排序当最终成绩。
4. 有可学习证据后，以完全相同的 80 轮配方做 T0/T1/T2/T3/T4 的匹配比较；后续独立种子验证最终候选。新增配置/推进门必须在看到该批结果前冻结，不能看到一组高分后跳过容量/普通注意力对照。
5. 最终按 Val 选定方案，再统一做 Test 比较。正常文字、保持长度的错配文字、绑定打乱等诊断用于归因，不能仅凭错误文字让性能降低就认领新模块价值。保留历史 Test 已被访问的事实。

RS1 提供的只可能是训练配方增益；文字候选需要超过相同配方的 T0/T1/T2，并由 T3/T4 消融说明额外机制的价值，才有资格讨论第二创新点。若普通注意力更好，优先保留 IoU 更好的方案并如实归因。
