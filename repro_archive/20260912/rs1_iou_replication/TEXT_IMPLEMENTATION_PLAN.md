# 中间解码层文字接口：实现规格草案

2026-09-13。承接 TEXT_NEXT.md，当前阶段完成的是源码定位和实现规格，不是新模型实现或训练结果。RS1 的共同配方选择以 replication_summary.json 的预先固定判定为准，不把训练 loss 的小幅收益认领为文字创新。

## 1. 已核实的代码入口

审计直接读取 Git 对象 `9eca26de5b301099805530edbf5a1a8718bea662` 的六个源码文件，记录 SHA256 和行锚点于 text_interface_audit.json；这些网络/分词源码与 R2 seed2027 一致。没有使用 docs 分支中可能较旧的网络文件定义实验。

`BetterLViT.encode_text` 返回 `[B,32,768]` token 状态，并将 attention mask 传入 `LViT.forward`。原模型的 Conv1d 文字链生成 `[B,32,128]` 的 `text2`；现有 EPPA 的文字通道投影和像素 FiLM 读取 CLS。原 EPPA 和原 token-to-patch 通路都保留。新增接口放在 FAM-EPPA 路径的 `d3 = self.up3(d4, x3, plam3, text=text)` 之后、`d2 = self.up2(...)` 之前。

| 张量 | 按源码推导的形状 |
|---|---|
| d4 | B×256×28×28 |
| 新接口输入 d3 | B×128×56×56 |
| d2 | B×64×112×112 |
| d1 | B×64×224×224 |
| 可复用文字 text2 | B×32×128 |

以上是静态推导，后续真实前向仍须核对形状和显存。选择 d3 使文字能够影响后续两级解码，避免只在最终概率的少量像素上修正；这只是待验证的设计理由，不是增益证据。

## 2. 首先实现的两个匹配对照

T1/T2 均使用 d3 的3136个位置作为 query，内部宽32、4个注意力头。Q/K/V 和输出投影均无bias，分别为128→32、128→32、128→32、32→128，query/context 各一个带仿射的 LayerNorm；每个新增接口共16,896个可训练参数。相同形状的参数用相同初始化，输出投影零初始化，其他投影正常初始化，固定残差系数0.1。只让输出投影为零，避免输出投影与乘法门同时为零使梯度断开。

| 组别 | 新增分支的 context | 需要控制的区别 |
|---|---|---|
| T0 | 无新增分支 | 原模型按相同训练预算执行 |
| T1 | 从 d3 自适应池化至4×8，得到32个128维视觉token | 新增容量与额外视觉计算 |
| T2 | 原文字链的 text2，并用原 attention mask 屏蔽padding key | 在相同接口容量上增加真实文字内容 |

T1的“纯视觉”只指新增分支；原LViT与EPPA本来就使用文字。T1不使用报告长度去删视觉token，避免把文本长度偷偷引入新增视觉分支。T2最大长度同为32，但有效key数随报告变化，不能声称两者实际attention计算完全相等。T2复用text2会对现有文字投影产生额外梯度，这属于待比较的新增文字路径效果；记录相关梯度，不能将其与新增参数量混淆。

padding key 不参加新增attention，不代表整个旧模型对padding状态完全不敏感：旧Conv1d可以混合相邻状态，原路径保持不改。空报告或无有效语义token时，新增分支直接返回零残差；原模型仍按原定义运行，不能声称整网变成无文字模型。避免对全masked行直接softmax导致NaN。

首轮只确定 T1/T2 是否能学且能超过同预算 T0；普通cross-attention是必要对照，不是第二创新点。若 T2 无收益，先诊断接口与梯度，不直接叠加短语、门控和新loss。

## 3. 后续短语和图像证据对照

T3以完整的位置短语为单位池化其对应的可见token，例如 upper left lung 与 lower right lung，保留侧别和上下位置的绑定。原 `audit_text_grounding_corpus.py::binding` 仅返回严格语法结构，并没有返回token span；实现时必须新增span映射，并验证映射后的token与当前tokenizer产生的原报告序列一致。无法解析、出现未知语法或无法可靠定位span时回到T2；不自动补写医学事实，不从mask中构造推理文字。

T3与T2沿用相同Q/K/V/输出维度和预算，额外分项报告“位置语义被明确绑定”的病例与其余病例。解析器只表达报告提及内容，未提及区域保持未知，不生成背景标签。新接口起步不加入固定图像左右/上下先验：当前legacy增强旋转/翻转图像而保留报告文字，直接套固定坐标会引入冲突；不能为了候选单独改变增强。

T4才加入由当前图像特征与文字匹配证据产生的影响强度，与T3单独比较。门初始应为可传梯度的中性值，不能和零输出投影形成双重零乘法；具体门结构、参数量及正则项要在实现注册时明确，不在本草案中假装已经冻结或训练。不得将sigmoid门值解释成校准后的医学置信度。

## 4. 执行边界

下一步建立独立开发工作树，实现T1/T2、CPU小张量检查，再冻结具体源SHA/tag和训练预算，随后运行真实Train CUDA预检。需要验证零初始化等价、masked key不影响新分支、空报告回退、前几步内输出层/内部投影均获得梯度、参数统计和训练吞吐。正式T0/T1/T2从同一配方与初始化比较；不把短步诊断等同于完整80轮成绩，也不根据短步排名提前挑唯一候选。后续T3/T4按 TEXT_NEXT.md 分项加入。

短语绑定、门控、普通图文attention都已有近邻研究；沿用[既有文献核查](../../20260911/text_grounding_research/REPORT.md)作为逐项对照清单，不能仅凭本草案命名就宣称新颖。只有相同配方下超过T0/T1/T2、再由T3/T4消融和最终Test验证，才讨论第二点的贡献。
